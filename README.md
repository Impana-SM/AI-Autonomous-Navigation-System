# AI Autonomous Navigation System

An experimental 2D autonomous-navigation workspace that combines visual perception, occupancy-grid mapping, route planning, and robot motion control. The project provides both a browser-based operations console and a standalone Pygame simulation.

## What It Includes

- YOLOv8-based object detection through the bundled `yolov8n.pt` model.
- Occupancy-grid generation from detected bounding boxes.
- 8-connected A* path planning in the standalone simulator.
- A Streamlit command center with A*, Dijkstra, and RRT route options.
- Editable maps, multi-robot missions, simulation controls, route analytics, and local run history.
- Offline image and video analysis in the Perception Lab. Webcam input is not used.

## Requirements

- Python 3.9 or newer is recommended.
- A desktop environment is required for the Pygame simulator.
- The first YOLO inference may take longer while the model and runtime initialize.

Install the dependencies in a virtual environment:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

If PowerShell blocks script activation, activate the environment using the terminal or shell of your choice and then run the same `pip install` command.

## Run the Application

### Streamlit command center

```bash
streamlit run app.py
```

The browser opens the NavOS Command Center. Use the sidebar to switch between:

| Workspace | Purpose |
| --- | --- |
| Mission Control | View the active map, fleet status, route length, and system overview. |
| Live Simulation | Advance or reset robots, run ten cycles, adjust speed, pause movement, and inspect telemetry. |
| Mission Planner | Configure robot start and goal cells, choose a planner, and compare route results. |
| Map Studio | Resize the grid, apply map presets, edit rectangular obstacles, and save maps. |
| Perception Lab | Upload an image or video, run detection on an image or the first video frame, and review results. |
| Route Inspector | Inspect waypoints, estimated route cost, turns, and download a route report. |
| Run History | Archive local mission records and export them as CSV. |

### Standalone Pygame simulator

```bash
python main.py
```

This starts a fixed 50 x 50 simulated world. Each loop captures the rendered frame, detects obstacles, builds an occupancy grid, plans a route to the goal, steers the robot toward the next waypoint, and stops when the goal is reached or the window is closed.

## Architecture

```text
app.py                         Streamlit command center and mission workflows
main.py                        Standalone perception-planning-control loop
src/perception.py              YOLO inference and occupancy-grid generation
src/planner.py                 A* path planner
src/controller.py              Kinematic steering controller
simulation/env_2d.py           Pygame world, rendering, and frame capture
data/maps.json                 Saved map presets
data/run_history.json          Archived local run records
outputs/                       Logs and recordings generated by workflows
```

The core standalone pipeline is:

```text
Rendered frame -> YOLO detections -> occupancy grid -> route -> steering command -> robot motion
```

The grid uses rows and columns. Obstacles are stored as rectangular tuples in the form `(row, column, height, width)`. Routes use 8-connected movement, allowing horizontal, vertical, and diagonal steps.

## Data and Model Files

- `yolov8n.pt` is the local YOLOv8 model used by `PerceptionEngine`.
- `data/maps.json` stores map dimensions and rectangular obstacles. The Streamlit app creates the file if it does not exist.
- `data/run_history.json` stores archived run records. The app creates the file if it does not exist.
- Uploaded video files used by the Perception Lab are written temporarily under `data/` and removed after the first frame is read.
- Generated logs and recordings belong under `outputs/`.

## Development Notes

The Streamlit interface is designed for deterministic, local simulation rather than hardware control. Its live simulation advances robot positions along calculated routes in discrete cycles. The standalone Pygame path uses the perception model on each frame and applies the controller to the simulated robot pose.

The current implementation has several intentional boundaries:

- It does not connect to real robot hardware, sensors, or a webcam.
- The standalone simulator uses the fixed environment defined in `simulation/env_2d.py`.
- Detection confidence is filtered at `0.3` in the standalone perception engine; the Streamlit upload workflow exposes its own confidence setting.
- Route planning can return no path when a start, goal, or corridor is blocked. Adjust the map or endpoints when that happens.

## Troubleshooting

- **`ModuleNotFoundError`**: activate the virtual environment and run `pip install -r requirements.txt` again.
- **Model load or inference errors**: confirm that `yolov8n.pt` is present in the project root and that OpenCV and Ultralytics installed successfully.
- **Pygame window does not appear**: run `python main.py` from a desktop session rather than a headless terminal or remote environment.
- **No route is shown**: check that the selected start and goal cells are inside the map and do not overlap an obstacle.
